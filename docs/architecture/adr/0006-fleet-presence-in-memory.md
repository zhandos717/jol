# 0006. Присутствие водителей в памяти

**Контекст.** Каждый водитель на линии шлёт координаты раз в 3–5 секунд. Через 5 секунд координата бесполезна. Поиск ближайших нужен на каждом шаге раздачи заказа.

**Решение.** `fleet` хранит присутствие в памяти процесса. Назначения «водитель → пассажир» хранятся отдельно от присутствия и восстанавливаются после рестарта из `dispatch.assignments`. Водитель без сигнала 90 секунд снимается с линии; приложение шлёт пульс раз в 30 секунд и само заново выходит на линию, если сервер его не знает.

**Альтернативы.** Redis GEO или NATS KV — дают несколько реплик `fleet`, но добавляют сетевой переход на горячем пути. PostgreSQL/PostGIS — слишком дорогая запись для данных, живущих секунды.

**Последствия.** ~10 000 обновлений в секунду на одном ядре, поиск ближайших за микросекунды. Один экземпляр `fleet`; при рестарте водители «возвращаются» за 30 секунд. Путь роста — шардирование по городам или H3-ячейкам.
