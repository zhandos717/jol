# 0002. NATS JetStream для событий, RPC и KV

**Контекст.** Нужны три вида связи: надёжные доменные события, быстрые синхронные запросы между сервисами и кратковременное хранилище ключей (фиксация цены).

**Решение.** NATS 2.11 с JetStream:
- события — стрим `JOL` (`jol.>`), durable-потребители с явным подтверждением, повтор через 2 с при ошибке, до 20 попыток;
- RPC — core request/reply с queue group = имя сервиса, это даёт балансировку между репликами без service discovery;
- KV — бакет `quotes` с TTL.

**Альтернативы.**
- *Kafka.* Сильнее в аналитике и долгом хранении, но тяжелее в эксплуатации (ZooKeeper/KRaft, разделы) и не даёт request/reply. Для этого масштаба избыточна.
- *RabbitMQ.* Хорош для очередей, но нет встроенного KV, а RPC через временные очереди сложнее.
- *HTTP между сервисами.* Нужен service discovery и retry-логика; асинхронные события всё равно понадобились бы.

**Последствия.** Один инфраструктурный компонент вместо трёх (брокер, Redis, discovery). Образ около 20 МБ, старт за миллисекунды. Обратная сторона — меньше готовых инструментов для анализа событий, чем у Kafka; при появлении аналитики события можно зеркалировать в хранилище.
