# 0007. Один активный dispatcher

**Контекст.** Раздача заказа — последовательность «предложить → ждать 15 с → следующему». Два экземпляра, раздающих один заказ, предложат его двум водителям сразу.

**Решение.** В демо `dispatch` работает в одном экземпляре; таймеры офферов живут в памяти. Корректность при этом обеспечивает база, а не память: принять заказ можно только через compare-and-set из `searching`, и уникальный индекс не даёт водителю иметь два активных заказа. После рестарта все заказы в `searching` раздаются заново.

**Альтернативы.** Распределённая очередь офферов с таймаутами (JetStream с `ack_wait` как таймером) — правильно для нескольких экземпляров, но сложнее отлаживать.

**Последствия.** Путь роста: партиционирование по городу (`dispatch-almaty`, `dispatch-astana`) и лидер на партицию через лок в NATS KV. Пересмотреть при запуске второго города.
