# 0003. База на сервис: роль и схема в общем кластере

**Контекст.** Сервисы не должны читать чужие таблицы, иначе схема одного становится скрытым контрактом для других. Отдельный кластер PostgreSQL на каждый сервис в демо слишком дорог.

**Решение.** Один кластер, но у каждого сервиса с состоянием своя роль и своя схема (`accounts`, `dispatch`, `intercity`), права на чужие схемы отозваны (`infra/postgres/init.sh`). Миграции лежат рядом с сервисом и применяются им самим при старте под advisory lock, поэтому реплики не гонятся друг с другом. Каждая колонка снабжена `COMMENT`.

**Альтернативы.** Общая схема с соглашением «не трогать чужое» — не защищает. Отдельные кластеры — правильно для продакшена с разными SLA, но для демо неоправданно.

**Последствия.** Данные других сервисов доступны только через события или RPC. Например, `dispatch` хранит снимок карточки водителя в заказе, а не делает JOIN с `accounts`. Переезд схемы в отдельный кластер — это смена `DATABASE_URL`, без изменения кода.
