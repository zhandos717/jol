# 0011. Идемпотентное создание заказа

**Контекст.** Пассажир нажимает «Заказать» несколько раз подряд или теряет связь на переходе, и приложение повторяет запрос. Повтор не должен ни создать второй заказ, ни вернуть ошибку «у вас уже есть заказ» вместо уже созданного.

**Решение.** Три уровня защиты:
1. **Клиент.** Кнопка блокируется на время запроса. Одно нажатие = один `Idempotency-Key` (UUID); при сетевой ошибке приложение повторяет запрос до 3 раз с тем же ключом и паузой 0.5 → 1 → 2 с.
2. **Сервис.** `dispatch` хранит ключ в заказе (`UNIQUE (client_id, idempotency_key)`). Повтор с тем же ключом возвращает исходный заказ с кодом 200, в том числе если два повтора пришли одновременно: проигравший вставку ловит нарушение уникальности и читает созданный заказ.
3. **База.** Частичный уникальный индекс «один активный заказ на пассажира» защищает даже от клиентов без ключа: второе нажатие с другим ключом получает 409.

Шлюз дополнительно ограничивает `POST /api/orders` до 2 запросов в секунду с всплеском 5 и отвечает 429 в JSON.

**Последствия.** Проверено сквозным тестом: три одновременных запроса с одним ключом → один заказ, три ответа 200 с одним id.
