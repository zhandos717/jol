# Такси-агрегатор

Демонстрационный сервис заказа такси для Казахстана: приложение пассажира, приложение водителя и сервер в реальном времени.

- **Такси** — Эконом, Комфорт, Бизнес; повышающий коэффициент при высоком спросе
- **Грузовое** — Каблук, Газель, Грузовик, грузчики
- **Межгород** — вся машина на дату и время или места с попутчиками
- **Рейтинги** пассажира и водителя, недавние адреса, отмена, пошаговый маршрут

## Быстрый старт

Нужны Docker с Compose и `make`.

```bash
make up
```

При первом запуске скачивается карта Казахстана с Geofabrik (~224 МБ) и готовится для маршрутов — на 1 vCPU это около 2–5 минут. Следить за процессом: `make logs-osrm`.

| Приложение | Адрес |
|---|---|
| Пассажир | http://localhost:8080/ |
| Водитель | http://localhost:8080/driver.html |

Чтобы проверить заказ на одном компьютере, откройте обе страницы в разных вкладках. У водителя включите «Симуляцию движения» — машина поедет по маршруту сама, без GPS.

## Команды

```
make help        список всех команд
make up          собрать и запустить
make down        остановить (данные сохраняются)
make logs        логи приложения
make health      проверить приложение и маршрутизацию
make psql        консоль PostgreSQL
make backup      дамп базы в backups/
make restore     восстановить: make restore FILE=backups/taxi-....dump
make map-reset   скачать свежую карту и пересобрать маршруты
make bench       нагрузочный тест: make bench DRIVERS=5000
make clean       удалить всё вместе с данными (спросит подтверждение)
```

## Как устроено

```
 Браузер пассажира ─┐                  ┌─► PostgreSQL 17   заказы, водители, пассажиры, рейсы
                    ├─► taxi (Node 22) ─┤
 Браузер водителя ──┘   :8080           └─► OSRM            маршруты по карте Казахстана
        │
        ├─► tile.openstreetmap.org   картинки карты
        └─► nominatim.openstreetmap.org   поиск адресов
```

| Сервис | Что делает |
|---|---|
| `taxi` | HTTP API, раздача заказов водителям, события в реальном времени через Server-Sent Events, раздача страниц |
| `postgres` | хранение; схема в `migrations/`, миграции применяются при старте |
| `osrm` | свой сервер маршрутов; браузер ходит к нему через `/osrm/...` на нашем сервере |
| `osrm-download`, `osrm-prepare` | одноразовые: скачать и подготовить карту, при повторных запусках пропускаются |

**Хранение.** Активные заказы и данные за последние 24 часа держатся в памяти и раз в 300 мс сохраняются в PostgreSQL — только изменившиеся записи, одной транзакцией. Координаты водителей в базу не пишутся. История (недавние адреса) читается из базы.

**Раздача заказа.** Ближайшему свободному водителю нужного тарифа (15 км в городе, 40 км для межгорода) уходит предложение на 15 секунд. Если водитель отказался или промолчал — следующему. Если за 90 секунд никто не взял, заказ получает статус «нет машин».

**Цена** считается только на сервере:

```
цена = (подача + км × ставка_за_км + мин × ставка_за_мин) × коэффициент + грузчики × 3000
```

Ставки — в `TARIFFS` в начале `server.js`.

**Коэффициент спроса.** Город поделён на зоны около 1.5 × 1.5 км. Для зоны с соседями: `спрос / свободные машины`, коэффициент от 1.0 до 2.5. Показанная пассажиру цена фиксируется на 3 минуты. На грузовое и межгород коэффициент не действует.

## Требования к серверу

### Сколько потребляет сейчас

Замер в Docker с 1 vCPU и 4 ГБ RAM на Apple Silicon:

| Компонент | Память | Диск |
|---|---|---|
| OSRM с картой Казахстана | ~570 МБ | 820 МБ (данные карты) |
| Приложение | ~90–120 МБ | 165 МБ (образ) |
| PostgreSQL | ~30 МБ на старте, растёт с базой | 290 МБ (образ) + данные |
| Подготовка карты (разово) | пик 725 МБ | — |

Пропускная способность на этом же железе, 2000 водителей онлайн (`make bench`):

| Запрос | req/s | p99 |
|---|---|---|
| Координаты водителя | ~10 600 | 20 мс |
| Машины рядом | ~2 200 | 46 мс |
| Карта спроса | ~4 900 | 20 мс |
| Расчёт цены (OSRM) | ~800 | 120 мс |

### Рекомендации

| Этап | CPU | RAM | Диск | Нагрузка |
|---|---|---|---|---|
| Демо и показы | 2 vCPU | 4 ГБ | 30 ГБ SSD | десятки пользователей |
| Пилот в одном городе | 4 vCPU | 8 ГБ | 60 ГБ SSD | до 1–2 тыс. водителей онлайн, несколько тысяч пассажиров |
| Несколько городов | отдельные машины под приложение, PostgreSQL и OSRM; Redis для координат и событий; несколько экземпляров приложения | | | |

Почему так:
- **RAM.** OSRM держит граф дорог в памяти (~600 МБ на Казахстан) — это главный потребитель. 4 ГБ хватает с запасом для ОС и PostgreSQL; на 2 ГБ подготовка карты может не пройти.
- **CPU.** Приложение — один процесс Node.js и использует одно ядро. Остальные ядра нужны OSRM и PostgreSQL.
- **Диск.** Карта и образы занимают ~2 ГБ, плюс база, логи и резервные копии. SSD обязателен для PostgreSQL.

Свой поиск адресов (Nominatim) по Казахстану потребует ещё 8+ ГБ RAM и ~50 ГБ диска.

### Что упрётся первым при росте

1. **Внешние сервисы карт.** Картинки карты и поиск адресов идут в публичные серверы OpenStreetMap. Их правила запрещают коммерческую нагрузку, а поиск ограничен ~1 запросом в секунду. Перед запуском нужен свой сервер тайлов и геокодер (свой Nominatim, 2GIS или Яндекс по договору).
2. **Один процесс приложения.** Состояние живёт в памяти, поэтому второй экземпляр рядом не поставить. Решение — Redis для координат и событий.
3. **Нет входа по SMS.** Пассажир и водитель определяются по случайному id в браузере.

| Переменная | По умолчанию | Назначение |
